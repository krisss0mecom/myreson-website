## Original problem

An engineering question from the project operator, not an outside participant.

RESON needs a portable record format that preserves provenance, conflicting claims and retractions when a different reader imports events in a different order. We have a candidate full-log contract, not a proven minimal design.

Find a counterexample or propose a smaller export that preserves the specified answers and cannot resurrect a retracted claim after a late duplicate. State whether future events and arbitrary new queries are allowed. Include one minimal case and a disconfirming test.

The naive last-import-wins baseline passes 4/12; the reference passes 12/12 under its own declared rules. This only checks synthetic fixtures, not real model migration or scientific generalization.

### reproduced: 3788a07c-cf78-437f-b2e6-5bebdfad3ff9_collision-loss

An export retaining active assertions and tombstones but dropping retracted assertion bodies loses ID-collision detection when a changed record with a retired ID arrives. Preserving the present answer and resisting exact duplicates does not establish equivalence under later mutations.

Verification: Operator-authored pilot/review_round1.py reran the published local resolve(): full and compact logs both give Porto before and after an exact duplicate; a mutated b gives invalid in the full log but Porto in the compact log. Eight checks and full synthetic inputs are published in /pilot/review_round1_report.json. No submitted code was executed. This is an example, not a universal proof.

### reproduced: 3788a07c-cf78-437f-b2e6-5bebdfad3ff9_global-invalidity

A collision for another entity or a retraction of a retraction makes the entire ledger invalid under the declared contract. This is an intentional rule with a denial-of-service concern for untrusted writers, not a newly discovered reader implementation bug.

Verification: The controlled reproduction checks a collision for lea while querying mira and a retract-of-retract. Both return invalid. A valid unrelated record does not by itself cause invalidity: the qualifier matters. The reference contract was not changed.

### hypothesis: 3788a07c-cf78-437f-b2e6-5bebdfad3ff9_hash-export-hypothesis

A per-ID fingerprint plus retained active records and tombstone information is a candidate repair, not yet an established equivalent compact representation. It needs an explicit importer and tests covering record kinds, invalid retractions, cross-entity arrivals, query assumptions and resource limits.

Verification: No general equivalence proof or full implementation of the proposed export was supplied in this submission. The reproduced example motivates keeping identity-change information; it does not validate the universal invariant. Distinguish evaluator input-size guards from ledger semantics.

### needs_revision: 3788a07c-cf78-437f-b2e6-5bebdfad3ff9_minimality-not-proved

The necessity of distinguishing certain past records does not prove that every valid representation must store one hash per ID. A finite cryptographic hash is a practical collision-resistant approximation, not an exact injective encoding of arbitrary records. Minimality and collision assumptions must be stated separately.

Verification: Logical review of the quantifier: failure of one export does not establish a storage lower bound over all representations. Exact equivalence and computational collision resistance are different guarantees. This is a qualification of the proposal, not a demonstrated cryptographic collision.

### hypothesis: 3788a07c-cf78-437f-b2e6-5bebdfad3ff9_scoped-invalidity-proposal

Scoping invalidity to affected IDs or entities could improve isolation, but it defines a different contract. Study it as a separately versioned policy rather than claiming it is a drop-in implementation of the current global-invalidity rules.

Verification: No implementation or reproduction of this changed policy was performed in this review. Dependencies between assertions and tombstones need explicit semantics and tests before adopting it.
